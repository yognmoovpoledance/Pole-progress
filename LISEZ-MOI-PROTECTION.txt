YOG’N MOOV · VERSION PROTÉGÉE (comptes + sauvegarde + accès réservé aux acheteuses)

IMPORTANT
Cette version n'a PAS pu être testée avec un vrai projet Firebase avant de te la remettre.
Suis la procédure de test à la fin et ne la mets pas en vente avant d'avoir validé chaque point.

CE QUI EST PROTÉGÉ ET CE QUI NE L'EST PAS
- Protégé (côté serveur, par les règles Firestore) : les comptes, l'accès et le carnet de chaque élève.
  Une personne qui n'a pas acheté peut créer un compte, mais ne peut ni lire ni écrire aucune donnée.
- Non protégé : le code de l'application et la liste des figures, des combos, des conseils et du lexique
  (figures.js) restent lisibles par quelqu'un qui sait chercher dans le code de la page.
  Pour les protéger aussi, il faudrait stocker ce contenu dans la base (étape suivante possible).
- Pas encore fait : export PDF, limite du nombre d'appareils, paiement automatique, textes légaux
  (politique de confidentialité, conditions de vente, RGPD) à faire valider.

COÛT
Firebase : offre gratuite « Spark », sans carte bancaire. Suffisante pour démarrer.
Ne passe pas à l'offre payante « Blaze » sans y avoir réfléchi : elle n'est pas nécessaire ici.

1. CRÉER LE PROJET FIREBASE (≈ 10 minutes, avec un compte Google)
   a. Va sur console.firebase.google.com > Ajouter un projet (nom : yognmoov-pole-progress). Désactive Google Analytics.
   b. Build > Authentication > Commencer > Méthode de connexion > « E-mail/Mot de passe » > Activer (pas le lien par e-mail) > Enregistrer.
   c. Authentication > Paramètres > Domaines autorisés > Ajouter : yognmoovpoledance.github.io
   d. Authentication > Modèles > « Validation de l'adresse e-mail » : choisis la langue Français (idem pour la réinitialisation du mot de passe).
   e. Build > Firestore Database > Créer une base de données > région « eur3 (Europe) » > mode PRODUCTION.
   f. Firestore > onglet Règles : remplace tout par le contenu de firestore.rules > Publier.

2. RELIER L'APPLICATION AU PROJET
   a. Roue dentée > Paramètres du projet > Général > Vos applications > icône « </> » (Web) > nom : pole-progress > Enregistrer.
   b. Copie les valeurs de firebaseConfig dans le fichier firebase-config.js (remplace les mots « REMPLACE... »).

3. AUTORISER UNE ACHETEUSE (à faire pour chaque vente, à la main)
   Firestore > Données > « Démarrer une collection » (la première fois) : ID de collection = acces
   ID du document = l'e-mail de l'acheteuse, EN MINUSCULES (ex. prenom.nom@gmail.com)
   Champ : actif (type booléen) = true
   Remboursement : passe actif à false (ou supprime le document). L'accès est coupé.

4. METTRE EN LIGNE SUR GITHUB
   Remplace TOUS les fichiers du dépôt par ceux de ce dossier (index.html, figures.js, auth.js, firebase-config.js, sw.js,
   manifest.webmanifest, dossier icons). Les fichiers LISEZ-MOI et firestore.rules sont facultatifs sur GitHub.

5. PROCÉDURE DE TEST (à faire dans cet ordre, chaque point doit réussir)
   [ ] Ouvre le lien : l'écran de connexion s'affiche, rien d'autre.
   [ ] Crée un compte avec une adresse e-mail QUI N'EST PAS dans la collection acces.
   [ ] Tu reçois l'e-mail de vérification ; après avoir touché le lien, l'écran « Accès non activé » s'affiche.
   [ ] Ajoute cette adresse dans acces (actif = true), puis touche « Réessayer » : l'application s'ouvre.
   [ ] Coche quelques figures, ferme l'application, rouvre-la : les coches sont toujours là.
   [ ] Connecte-toi avec le même compte depuis un autre téléphone : les mêmes coches apparaissent.
   [ ] Passe actif à false : après « Réessayer » / reconnexion, l'accès est refusé.
   [ ] « Mot de passe oublié » : tu reçois un e-mail et peux choisir un nouveau mot de passe.
   [ ] « Exporter mes données » télécharge un fichier.
   [ ] « Supprimer mon compte et mes données » supprime le compte (à tester avec un compte de test).
   [ ] Installe l'application sur l'écran d'accueil (Android : menu ⋮ > Installer ; iPhone : Partager > Sur l'écran d'accueil).
   Si un point échoue, note le message affiché et envoie-le moi.

SÉCURITÉ : ce qu'il faut savoir
- Les valeurs de firebase-config.js ne sont pas secrètes ; c'est normal qu'elles soient visibles.
  La protection vient des règles Firestore (firestore.rules) : ne les modifie pas sans me demander.
- L'e-mail doit être vérifié : cela empêche quelqu'un de créer un compte avec l'e-mail d'une acheteuse qui n'est pas la sienne.
- Tu vois les carnets dans la console Firebase (tu en es l'administratrice) : prévois de l'indiquer dans ta politique de confidentialité.


6. TEXTES LÉGAUX (mentions-legales.html, confidentialite.html, cgv.html)
   Ce sont des MODÈLES, pas des conseils juridiques. Remplace chaque texte surligné [À COMPLÉTER ...],
   vérifie les coordonnées des hébergeurs, puis fais relire l'ensemble (ton expert-comptable, la CCI, ou un juriste).
   La case à cocher de renonciation au droit de rétractation doit être ajoutée sur ton site de vente, avant le paiement.
   Ne mets pas l'application en vente tant qu'ils ne sont pas complétés.

7. PROTÉGER LE CODE ET LE CONTENU
   - Le code d'une application web est envoyé au navigateur : on ne peut pas le cacher complètement.
   - Protection réelle possible (étape suivante) : stocker les figures, combos, conseils et lexique dans la base protégée,
     lisible uniquement après connexion par les acheteuses. Le code seul ne contient alors plus ton contenu.
   - Protection partielle : brouiller le code (obfuscation). Elle ralentit une copie mais ne l'empêche pas.
   - Protection juridique : les mentions légales et les CGV interdisent la copie et la revente.
